# Ulala Frontend Web Service Design Principle

1. 기본 원칙

- 화면 전체에서 버튼, 컬러, 폰트, 간격을 일관되게 사용하라.
- 텍스트는 충분한 크기와 줄 간격을 주어 읽기 쉽게 디자인하라.
- 텍스트와 배경의 색상 대비를 WCAG 기준(최소 4.5:1) 이상으로 맞춰라.
- 한 화면에는 필요한 정보만 배치하고, 핵심 행동(CTA 버튼)을 가장 눈에 띄는 곳에 두어라.

2. 타이포그래피

- 폰트는 1개만 사용하고(필요시 최대 2개), 제목·본문·캡션 2~3단계로 단순하게 구분하라.
- 줄 간격(line-height)은 글자가 숨 쉴 수 있게 1.4~1.6배로 설정하라.
- 제목과 본문은 명확히 크기 차이를 두어라.

3. 컬러 시스템

- 메인(primary), 보조(secondary), 포인트(accent), 중립(neutral) 컬러를 미리 정의하고 사용하라.
- 성공(초록), 실패(빨강), 경고(노랑), 정보(파랑) 상태 컬러를 반드시 구분해 두어라.
- 다크 모드와 라이트 모드에서 컬러가 무너지지 않도록 대비를 점검하라.

4. 레이아웃 & 간격

- 마진과 패딩은 8px 또는 4px 단위를 기준으로 정렬하라.
- 반응형 디자인은 모바일 우선(Mobile First) 으로 설계하고, 점진적으로 화면을 확장하라.
- 버튼과 입력창 같은 주요 요소 사이에는 충분한 여백을 두어라.

5. 컴포넌트

- 버튼에는 기본 / hover / active / disabled / loading 상태를 모두 구현하라.
- 입력창에는 placeholder, error 메시지, focus 상태를 반드시 포함하라.
- 리스트와 카드는 반복되는 데이터가 같은 UI 패턴으로 보이도록 설계하라.
- 알림(Toast), 모달, 배지 같은 피드백 요소를 적절한 상황에서 사용하라.

6. 인터랙션 & 모션

- 클릭, 입력 등 사용자 행동에 즉각적인 시각적 반응을 제공하라.
- 애니메이션은 150~300ms 사이의 빠르고 자연스러운 전환으로 구현하라.
- 불필요한 모션은 줄이고, 사용성을 돕는 경우에만 적용하라.

7. 접근성

- 모든 버튼과 링크는 키보드(Tab)로 접근 가능하게 하라.
- 이미지에는 반드시 대체 텍스트(alt) 를 작성하라.
- 폼 요소에는 Label 또는 aria 속성을 붙여 스크린리더에서 읽히도록 하라.
- 색상만으로 상태를 구분하지 말고, 아이콘이나 텍스트도 함께 제공하라.

8. 콘텐츠 & 카피

- 버튼과 메시지는 짧고 동사 중심으로 작성하라. (예: “등록하기”, “저장됨”)
- 한 문장은 20자 내외로 간결하게 작성하라.
- 사용자가 다음에 무엇을 해야 하는지 문구로 분명하게 안내하라.
