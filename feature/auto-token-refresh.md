# 자동 토큰 갱신 기능 명세서

**상태**: ✅ 구현 완료 (2025-11-16)

**구현된 파일**:
- `app/api/api.ts` - API 클라이언트 수정 (401 에러 인터셉터, 자동 재시도)
- `app/contexts/AuthContext.tsx` - 토큰 갱신 관리 및 주기적 갱신

**주요 변경사항**:
- API 요청 시 401 에러 자동 감지 및 토큰 갱신 후 재시도
- 토큰 갱신 중복 요청 방지 메커니즘
- 55분마다 자동 토큰 갱신 (만료 5분 전)
- Page Visibility API를 활용한 백그라운드 탭 최적화
- 토큰 갱신 관련 모든 로그 제거 (조용한 백그라운드 작업)

## 개요

### 현재 문제점
- 사용자가 브라우저를 오랫동안 켜놓으면 액세스 토큰(1시간 유효)이 만료됨
- Stories 탭에서 태스크 수정 등 작업 중 API 요청이 실패하여 사용자가 입력한 내용이 사라짐
- 리프레시 토큰(1주일 유효)은 유효하지만 자동으로 갱신되지 않음

### 해결 목표
- API 요청 실패 시 자동으로 액세스 토큰을 갱신하고 원래 요청을 재시도
- 사용자가 작업을 중단하지 않고 계속 진행할 수 있도록 투명한 토큰 갱신 제공
- 토큰 만료 전 자동 갱신으로 요청 실패를 사전에 방지

## 요구사항

### 기능적 요구사항

1. **API 요청 인터셉터 구현**
   - 모든 API 요청에 대해 401 Unauthorized 에러 감지
   - 401 에러 발생 시 자동으로 토큰 갱신 시도
   - 토큰 갱신 성공 시 원래 요청을 새 토큰으로 재시도
   - 토큰 갱신 실패 시 사용자를 로그인 페이지로 리다이렉트

2. **토큰 갱신 중복 요청 방지**
   - 여러 API 요청이 동시에 401 에러를 받을 경우 토큰 갱신은 한 번만 수행
   - 갱신 중인 동안 대기 중인 요청들은 갱신 완료 후 새 토큰으로 재시도

3. **주기적 토큰 갱신 (선택적)**
   - 액세스 토큰 만료 전(예: 55분 시점)에 자동으로 갱신
   - 사용자가 활동 중일 때만 갱신 (탭이 백그라운드일 때는 제외)

4. **토큰 갱신 실패 처리**
   - 리프레시 토큰도 만료된 경우 (1주일 경과)
   - 사용자에게 세션 만료 알림 표시
   - 로그인 상태 초기화 및 로그인 페이지로 이동

### 비기능적 요구사항

1. **사용자 경험**
   - 토큰 갱신 과정이 사용자에게 투명하게 진행
   - 작업 중단 없이 자연스럽게 요청 재시도
   - 토큰 갱신 실패 시에만 명확한 피드백 제공

2. **성능**
   - 토큰 갱신 중 동시 요청들이 적절히 대기
   - 불필요한 중복 갱신 방지
   - 최대 1회 재시도로 제한하여 무한 루프 방지

3. **보안**
   - 새로운 액세스 토큰은 메모리에만 저장 (현재 AuthContext 방식 유지)
   - 리프레시 토큰은 HttpOnly 쿠키로 관리 (현재 방식 유지)

## 테스트 계획

### 수동 테스트 시나리오

1. **기본 토큰 갱신 테스트**
   - 브라우저를 1시간 이상 켜놓고 태스크 수정 시도
   - 자동으로 토큰이 갱신되고 작업이 정상 완료되는지 확인

2. **동시 요청 테스트**
   - 여러 API 요청을 동시에 보내고 모두 401 에러 발생 시
   - 토큰 갱신이 한 번만 수행되고 모든 요청이 재시도되는지 확인

3. **리프레시 토큰 만료 테스트**
   - 리프레시 토큰이 만료된 상태에서 API 요청 시도
   - 적절한 에러 메시지와 함께 로그인 페이지로 이동하는지 확인

4. **백그라운드 탭 테스트** (주기적 갱신 구현 시)
   - 탭을 백그라운드로 전환 후 다시 활성화
   - 불필요한 갱신이 발생하지 않는지 확인

### 검증 방법

1. 브라우저 개발자 도구 Network 탭에서 API 요청 흐름 확인
2. Console 로그로 토큰 갱신 시점 및 재시도 확인
3. 다양한 시간대에 사용자 작업 시뮬레이션

## 구현 세부사항

### 1. API 클라이언트 수정 (`app/api/api.ts`)

#### 추가된 기능

1. **토큰 갱신 콜백 시스템**
   ```typescript
   // AuthContext에서 토큰 갱신 함수를 등록할 수 있는 시스템
   let refreshTokenCallback: RefreshTokenCallback | null = null;
   export function setRefreshTokenCallback(callback: RefreshTokenCallback)
   ```

2. **중복 갱신 방지 메커니즘**
   ```typescript
   // 여러 요청이 동시에 401을 받아도 토큰 갱신은 한 번만 수행
   let refreshTokenPromise: Promise<string | null> | null = null;
   ```

3. **401 에러 인터셉터**
   - `request()` 함수에서 401 응답 자동 감지
   - 토큰 갱신 시도 후 새로운 토큰으로 자동 재시도
   - `_isRetry` 플래그로 무한 루프 방지 (최대 1회 재시도)

#### 동작 흐름

1. API 요청 → 401 Unauthorized 응답
2. `refreshToken()` 함수 호출
3. 이미 갱신 중이면 기존 Promise 반환 (중복 방지)
4. 등록된 콜백 함수로 새 토큰 발급
5. 새 토큰으로 원래 요청 재시도
6. 갱신 실패 시 401 응답 그대로 반환

### 2. AuthContext 수정 (`app/contexts/AuthContext.tsx`)

#### 추가된 상태 관리

1. **토큰 만료 시간 추적**
   ```typescript
   const tokenExpiryTimeRef = useRef<number | null>(null);
   // 현재 시간 + 1시간으로 설정
   ```

2. **주기적 갱신 타이머**
   ```typescript
   const refreshTimerRef = useRef<NodeJS.Timeout | null>(null);
   // 55분 후 자동 갱신
   ```

#### 추가된 함수

1. **`setTokenWithExpiry(token)`**
   - 토큰 설정 시 만료 시간도 함께 기록
   - 자동으로 주기적 갱신 타이머 시작

2. **`startRefreshTimer()`**
   - 55분 후 자동 갱신 타이머 시작
   - 기존 타이머가 있으면 먼저 정리

3. **`stopRefreshTimer()`**
   - 갱신 타이머 중지 및 정리

4. **토큰 갱신 콜백 등록**
   - `useEffect`에서 `setRefreshTokenCallback()` 호출
   - API 클라이언트가 호출할 수 있도록 등록

#### Page Visibility API 통합

- 탭이 백그라운드로 전환되면 타이머 중지
- 탭이 다시 활성화되면:
  - 토큰이 만료되었거나 곧 만료될 경우 즉시 갱신
  - 토큰이 유효하면 타이머 재시작

### 3. 개선된 사용자 경험

1. **투명한 토큰 갱신**
   - 사용자는 토큰 갱신을 인지하지 못함
   - 작업 중단 없이 자연스럽게 계속 진행

2. **성능 최적화**
   - 백그라운드 탭에서는 불필요한 갱신 방지
   - 중복 갱신 요청 방지로 서버 부하 감소

3. **사전 갱신 전략**
   - 만료 5분 전(55분)에 미리 갱신
   - 요청 실패 가능성 최소화

### 4. 조용한 백그라운드 작업

- 모든 토큰 갱신 로그가 제거되어 콘솔이 깨끗하게 유지됩니다
- 토큰 갱신은 사용자에게 완전히 투명하게 진행됩니다
- 필요시 브라우저 개발자 도구의 Network 탭에서 `/api/auth/token` 요청을 통해 확인 가능합니다

### 5. 테스트 방법

#### 개발 환경에서 테스트

1. **토큰 만료 시뮬레이션**
   - 브라우저 개발자 도구 Network 탭을 열어둡니다
   - Stories 탭에서 태스크를 수정합니다
   - Network 탭에서 401 응답 후 자동으로 `/api/auth/token` 요청이 발생하고 원래 요청이 재시도되는지 확인합니다

2. **주기적 갱신 확인**
   - 브라우저를 55분 이상 켜둡니다
   - Network 탭에서 주기적으로 `/api/auth/token` 요청이 발생하는지 확인합니다

3. **백그라운드 탭 동작**
   - 다른 탭으로 이동했다가 다시 돌아옵니다
   - 토큰이 만료되었을 경우 즉시 갱신되는지 Network 탭에서 확인합니다

### 6. 알려진 제한사항

1. **최대 1회 재시도**
   - 토큰 갱신 후에도 401이 발생하면 더 이상 재시도하지 않음
   - 무한 루프 방지를 위한 설계

2. **리프레시 토큰 만료 시**
   - 현재는 조용히 실패 (accessToken이 null로 설정됨)
   - 향후 사용자에게 명시적인 알림 또는 로그인 페이지 리다이렉트 추가 가능

3. **타이머 정확도**
   - JavaScript의 `setTimeout`은 정확하지 않을 수 있음
   - 백그라운드 탭에서는 브라우저가 타이머를 throttle할 수 있음
   - Page Visibility API로 탭 활성화 시 보완

### 7. 향후 개선 사항

1. **에러 모니터링 통합**
   - Sentry 등과 연동하여 토큰 갱신 실패 추적

2. **사용자 피드백**
   - 리프레시 토큰 만료 시 명시적인 알림
   - 토스트 메시지로 재로그인 안내

3. **옵티미스틱 갱신**
   - 토큰이 곧 만료될 것으로 예상되면 요청 전 미리 갱신

4. **네트워크 상태 감지**
   - Navigator Online/Offline API 활용
   - 오프라인 상태에서는 불필요한 갱신 시도 방지
