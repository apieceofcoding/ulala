# 프로필 수정 기능 명세서

**상태**: 📝 작성 완료 (승인 대기)
**관련 파일**:

- app/routes/profile.tsx (프로필 페이지)
- app/routes/profile.edit.tsx (프로필 수정 페이지 - 신규)
  **API 엔드포인트**: /api/members/me (업데이트 필요)

## 개요

사용자가 자신의 프로필 정보를 직접 수정할 수 있는 기능입니다. 사용자이름(username)와 이름(displayName)을 변경할 수 있습니다.

프로필 수정은 **별도의 페이지(/profile/edit)**에서 진행되며, 수정 완료 후 프로필 페이지로 다시 돌아옵니다.

### 목적과 필요성

- 사용자가 자신의 프로필을 개인화하고 관리할 수 있는 기능 제공
- 사용자이름 변경을 통한 고유 식별자 관리
- 닉네임 변경을 통한 개성 표현
- 별도 페이지로 수정 기능을 분리하여 명확한 사용자 플로우 제공

## 요구사항

### 기능적 요구사항

1. **프로필 수정 페이지 진입**
   - 프로필 페이지(/profile)에 "수정" 버튼 추가
   - 클릭 시 프로필 수정 페이지(/profile/edit)로 이동 (React Router navigate)
   - 로그인된 사용자만 접근 가능
   - 로그인하지 않은 사용자 접근 시 프로필 페이지로 리다이렉트

2. **사용자이름(username) 변경 기능**
   - 현재 username를 입력창에 표시
   - 텍스트 입력으로 새로운 사용자이름 입력
   - 유효성 검증:
     - 6자 이상 20자 이하
     - 영문 대소문자, 숫자, 언더스코어(\_)만 허용
     - 중복 확인 필수 (서버 측 검증)
     - 필수 입력 (비워둘 수 없음)
   - **실시간 중복 확인 (Debounce)**:
     - 입력 후 1초 대기 후 자동으로 중복 확인 API 호출
     - API: `/api/members/{username}/check`
     - 디바운스를 통해 불필요한 API 호출 방지
   - **시각적 피드백**:
     - 중복 확인 중: 로딩 스피너 아이콘 표시
     - 사용 가능: 초록색 체크 아이콘 (✓) + "사용 가능한 ID입니다" 메시지
     - 중복됨: 빨간색 X 아이콘 (✗) + "이미 사용 중인 ID입니다" 메시지
     - 유효하지 않음: 빨간색 경고 아이콘 + 에러 메시지

3. **이름(displayName) 변경 기능**
   - 현재 displayName을 입력창에 표시
   - 텍스트 입력으로 새로운 이름 입력
   - 유효성 검증:
     - 0자 이상 20자 이하
     - 특수문자 제한 (기본 한글, 영문, 숫자, 공백 허용)
     - 선택 입력 (비워둘 수 있음)
   - 실시간 글자 수 표시

4. **저장 및 취소**
   - "저장하기" 버튼으로 변경사항 서버 전송
   - "취소" 버튼 클릭 시 프로필 페이지(/profile)로 돌아가기
   - 저장 시 로딩 상태 표시
   - 성공/실패 피드백 제공
   - 저장 성공 시 프로필 페이지(/profile)로 자동 이동

5. **데이터 동기화**
   - 프로필 정보 API: `/api/members/me` (PATCH) 호출
   - 성공 시 로컬 상태 업데이트
   - 실패 시 에러 메시지 표시 및 이전 상태 유지

### 비기능적 요구사항

- 반응형 디자인 적용
- 네트워크 에러 처리
- 접근성 준수 (키보드 네비게이션, 스크린 리더)
- 라이트/다크 모드 지원
- 빠른 응답 속도

## 디자인 고려사항

### docs/design-guide.md 적용 원칙

1. **일관성 (Consistency)**
   - 기존 버튼, 입력 필드 스타일 재사용
   - 모달/카드 디자인 통일
   - 동일한 색상 시스템 적용

2. **가독성 (Readability)**
   - 명확한 라벨과 placeholder
   - 에러 메시지를 아이콘과 함께 표시
   - 충분한 색상 대비 (WCAG AA 기준 4.5:1)

3. **단순성 (Simplicity)**
   - 한 화면에 필요한 정보만 표시
   - 수정 모드에서는 수정 가능한 필드만 강조
   - 명확한 CTA (저장하기 버튼)

4. **자연스러운 구분 (Natural Separation)**
   - 테두리 대신 배경색과 그림자로 구분
   - 카드 스타일 일관성 유지

### 사용할 컴포넌트와 색상 시스템

1. **버튼 컴포넌트**
   - Primary 버튼: `btn-primary` (저장하기)
   - Secondary 버튼: `btn-secondary` (취소, 수정)
   - 로딩 상태: `btn-loading`
   - 5가지 상태 모두 구현 (기본/hover/active/disabled/loading)

2. **입력 필드**
   - 기본 입력: `input-default`
   - 에러 상태: `input-error`
   - 라벨: `input-label`
   - 에러 메시지: `error-message`

3. **색상 시스템**
   - 텍스트: `text-primary`, `text-secondary`, `text-tertiary`
   - 배경: `bg-primary`, `bg-secondary`, `bg-tertiary`
   - Primary 색상: `bg-primary`, `text-primary`
   - 에러 색상: `text-error`, `border-error`

4. **간격 시스템**
   - 8px 기반 간격 사용
   - `spacing-s` (8px), `spacing-m` (16px), `spacing-l` (24px)

5. **모달/카드**
   - 카드 스타일: `card-default`
   - 그림자: `shadow-low`, `shadow-medium`

## 구현 계획

### 1단계: UI 구조 설계

1. **프로필 페이지(/profile)에 수정 버튼 추가**
   - 프로필 헤더 우측 상단에 "수정" 버튼 배치
   - 아이콘 + 텍스트 형태
   - 클릭 시 `/profile/edit`로 navigate

2. **프로필 수정 페이지(/profile/edit) 구성**
   - 전체 화면 페이지로 구현
   - 상단에 TopBar 또는 헤더 배치
     - 뒤로가기 버튼 (← 아이콘)
     - 제목: "프로필 수정"
   - 하단에 BottomNav 유지 (선택사항)

3. **사용자이름 입력 필드 상태별 표시**:
   - 입력 중: 기본 상태
   - 검증 중 (1초 대기 후): 로딩 스피너 표시
   - 사용 가능: ✓ 초록색 체크 + "사용 가능한 ID입니다"
   - 중복됨: ✗ 빨간색 X + "이미 사용 중인 ID입니다"
   - 유효하지 않음: ⚠ 빨간색 경고 + 에러 메시지

### 2단계: 사용자이름 입력 필드 UI 구현

1. **사용자이름 입력 필드 구성 요소**
   - 라벨: "사용자이름"
   - 입력 필드: text 타입, placeholder 표시
   - 상태별 아이콘: 입력 필드 우측에 절대 위치로 배치
     - checking: 로딩 스피너 (애니메이션 회전)
     - available: 체크 아이콘 (초록색)
     - taken: X 아이콘 (빨간색)
     - invalid: 경고 아이콘 (빨간색)
   - 상태 메시지: 입력 필드 하단에 표시
     - available: 초록색 텍스트
     - taken/invalid: 빨간색 텍스트
   - 가이드 텍스트: "6-20자, 영문 대소문자, 숫자, \_ 사용 가능"

2. **입력 필드 스타일 처리**
   - 기본 상태: `input-default` 클래스
   - 에러 상태 (invalid/taken): `input-error` 클래스 (빨간색 테두리)
   - 우측 패딩 추가: 아이콘 공간 확보

### 3단계: 라우팅 설정

1. **React Router 라우트 추가**
   - 프로필 페이지 라우트: `/profile`
   - 프로필 수정 페이지 라우트: `/profile/edit`
   - 라우트 설정 파일: `app/routes.ts` 또는 `App.tsx`

2. **페이지 이동 로직 (프로필 페이지)**
   - React Router의 `useNavigate` 훅 사용
   - "수정" 버튼 클릭 시 로그인 여부 확인
   - 로그인하지 않은 경우 안내 메시지 표시
   - 로그인한 경우 `/profile/edit`로 이동

3. **페이지 이동 로직 (프로필 수정 페이지)**
   - "취소" 버튼 클릭 시 `/profile`로 이동
   - 저장 성공 시 `/profile`로 이동
   - 뒤로가기 버튼 클릭 시 `/profile`로 이동

### 4단계: 폼 상태 관리

1. **상태 변수 (프로필 수정 페이지)**
   - `username`: 사용자이름 입력값
   - `displayName`: 이름 입력값
   - `isSaving`: 저장 중 상태
   - `isCheckingUsername`: 사용자이름 중복 확인 중 상태
   - `usernameStatus`: 사용자이름 검증 상태 ('idle' | 'checking' | 'available' | 'taken' | 'invalid')
   - `usernameMessage`: 사용자이름 상태 메시지
   - `errors`: 각 필드별 에러 메시지 객체

2. **유효성 검증 및 중복 확인 로직**
   - **Debounce 타이머 관리**:
     - useRef로 타이머 참조 보관
     - 컴포넌트 언마운트 시 타이머 정리

   - **사용자이름 유효성 검증 함수**:
     - 6-20자 길이 확인
     - 영문 대소문자, 숫자, \_ 만 허용하는지 정규식으로 확인
     - 유효하지 않으면 에러 상태 및 메시지 설정

   - **사용자이름 중복 확인 함수** (비동기):
     - 기본 유효성 검증 먼저 수행
     - 기존 ID와 동일하면 검증 생략
     - API 호출: `/api/members/{username}/check`
     - 응답에 따라 상태 업데이트 (available, taken, invalid)
     - 에러 시 logger로 로그 기록 및 에러 상태 설정

   - **사용자이름 입력 핸들러** (Debounce 적용):
     - 입력값 변경 시 상태 초기화 (idle)
     - 기존 타이머가 있으면 취소
     - 빈 값이면 검증 생략
     - 1초 후 중복 확인 함수 실행

   - **이름 유효성 검증 함수**:
     - 0-20자 길이 확인
     - 유효하지 않으면 에러 메시지 설정

### 5단계: API 연동

1. **API 엔드포인트 추가**
   - `app/api/endpoints.ts` 파일에 다음 엔드포인트 추가:
     - `ME`: `/api/members/me` (현재 사용자 정보 조회)
     - `UPDATE_PROFILE`: `/api/members/me` (PATCH - 프로필 정보 업데이트)
     - `CHECK_USERNAME`: `/api/members/{username}/check` (GET - username 중복 확인)

   **API 응답 형식**:
   - 중복 확인 API: `GET /api/members/{username}/check`
     - 성공 응답: `{ "exists": false }` (사용 가능) 또는 `{ "exists": true }` (중복)

2. **프로필 업데이트 로직**
   - **저장 전 검증**:
     - username와 displayName 유효성 검증
     - username가 기존과 다르면 중복 확인 API 호출
     - 검증 실패 시 저장 중단

   - **저장 프로세스**:
     1. 저장 중 상태 활성화 (`isSaving: true`)
     2. 프로필 정보 업데이트 API 호출 (PATCH `/api/members/me`):
        - JSON 형식으로 username, displayName 전송
        - accessToken을 헤더에 포함
        - Content-Type: application/json 설정
     3. 성공 시:
        - 서버에서 받은 업데이트된 회원 정보로 상태 갱신
        - 성공 메시지 표시 (alert 또는 toast)
        - `/profile` 페이지로 이동
     4. 실패 시:
        - logger로 에러 로그 기록
        - 사용자에게 에러 메시지 표시
     5. 완료 후 저장 중 상태 비활성화 (`isSaving: false`)

### 6단계: 반응형 구현

1. **페이지 레이아웃 반응형**
   - **모바일**: 전체 너비, 좌우 패딩 4 (16px), 상하 패딩 6 (24px)
   - **태블릿 이상** (768px 이상): 최대 너비 md (448px), 중앙 정렬, 좌우 패딩 6 (24px)
   - **데스크톱** (1024px 이상): 최대 너비 lg (512px)
   - Tailwind CSS의 반응형 유틸리티 클래스 사용

2. **터치 최적화**
   - 버튼 최소 크기: 44x44px (터치 타겟 권장 크기)
   - 요소 간 충분한 간격: 8px 이상 (8px 기반 간격 시스템 활용)

### 7단계: 에러 처리 및 피드백

1. **에러 케이스**
   - 네트워크 에러
   - 서버 에러 (400, 401, 500 등)
   - 유효성 검증 실패

2. **피드백 UI**
   - 에러 메시지: 입력 필드 아래에 빨간색으로 표시
   - 성공 토스트: 화면 상단에 표시
   - 로딩 상태: 버튼에 스피너 표시

## 보안 고려사항

1. **인증 및 권한**
   - 로그인된 사용자만 수정 가능
   - accessToken을 Authorization 헤더로 전송
   - 토큰 만료 시 재발급

2. **입력 검증**
   - XSS 방지: username, displayName 입력값 sanitize
   - SQL Injection 방지: 서버 측 파라미터 바인딩
   - username 중복 확인: 서버 측에서 재검증
